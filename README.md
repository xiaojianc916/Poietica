> **Poietica does not try to create instead of you.**  
> It helps you keep creating while your thoughts are still incomplete.

Creative work rarely begins with a polished plan. It starts with an unfinished sentence, a question, a reference, a sketch, a feeling, or a direction that has not become clear yet.

Poietica brings those fragments into one place. You can write, collect, connect, rearrange, question, and develop them at your own pace.

<details>
<summary><strong>Why local-first matters</strong></summary>

<br>

Your work belongs to you.

Poietica is designed around predictable local document behavior:

- save and recovery should be dependable;
- files should behave clearly rather than mysteriously;
- exports should remain under your control;
- network and AI requests should only happen through explicit product flows;
- external AI services should receive only the context intentionally selected for them.

</details>

## ⚑ Current status

> **Active development**  
> The current focus is the reliable foundation: documents, assets, editor behavior, desktop capabilities, recoverable file operations, typed IPC, and bounded AI workflows.

The project is intentionally building reliability before broadening the product surface. The goal is not merely to add features quickly, but to create a creative environment that remains trustworthy as it grows.

## Architecture, briefly

Poietica is a monorepo with intentionally strict ownership boundaries.

```text
apps/          Final desktop application composition
editor/        Canvas, documents, assets, persistence, and extensions
features/      AI, settings, workspace, and product-facing capabilities
foundations/   Shared primitives and design-system building blocks
platforms/     Desktop runtime adapters and typed IPC contracts
docs/          Architecture notes, ADRs, RFCs, and operational guides
tests/         Architecture, integration, and product verification
```

> **Important:** for canvas documents, tldraw's `Editor` and `TLStore` are the only source of truth.  
> Shapes, bindings, assets, pages, and canvas records must not be mirrored into a second document model.

The full architecture belongs in the documentation—not in this README.

## Contributing

Contributions should preserve the guarantees that make Poietica trustworthy:

- **one source of truth** for each kind of state;
- **one normal write path** for canvas changes, with undo/redo remaining reliable;
- **no silent AI edits** to user work;
- **explicit and minimal AI context** for external requests;
- **validated boundaries** for files, paths, images, clipboard data, AI output, plugins, and IPC;
- **no platform capability leakage** into product-domain or foundation packages;
- **no permanent parallel implementations** created as shortcuts.

Before opening a pull request, run:

```bash
pnpm check
pnpm clippy
pnpm audit
pnpm audit:rust
```
